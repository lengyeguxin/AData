## 配置管理

### 配置文件位置

**主配置：** `code/backend/config/config.yaml`

**软链接：** `code/frontend/config/config.yaml` → `code/backend/config/config.yaml`

**注意：** 修改配置时，统一修改backend的config.yaml（前端通过软链接读取）

---

### 关键配置项

#### 1. Tushare API配置

```yaml
tushare:
  token: bd829d8919ffcdc1d18c...  # 您的Token
  api_url: http://lianghua.nanyangqiankun.top  # 代理地址
  rate_limit: 500  # 速率限制（次/分钟）
```

**重要：**
- 必须使用代理地址（http://lianghua.nanyangqiankun.top）
- 官方地址可能不支持您的Token
- IP限制：最多2个IP同时使用

---

#### 2. 数据拉取配置

```yaml
fetch:
  enabled: true              # 拉取开关（全局）
  start_date: "20210101"     # 最早开始时间
  check_interval: 60         # 检测间隔（分钟）
```

**开关控制：**
- `enabled: true` - 自动拉取（main.py启动时）
- `enabled: false` - 禁止拉取（仅初始化数据库）

---

#### 3. 快照配置

```yaml
snapshot:
  enabled: true              # 快照开关
  interval: 90               # 快照间隔（分钟）
  locations:                 # 快照位置（双备份）
    - database/adata_snapshot.db
    - /home/my/claude-project/AiStock/database/adata_snapshot.db
```

**推荐设置：**
- interval: 30-90分钟（平衡性能和安全）
- 双位置备份（跨项目共享数据）

---

#### 4. 调度器配置

```yaml
scheduler:
  daily_update_time: "18:00"      # 日线更新时间
  weekly_update_time: "19:00"     # 周线更新时间
  monthly_update_time: "19:00"    # 月线更新时间
```

**18点判断逻辑：**
- 当前时间≥18:00：拉取今天数据
- 当前时间<18:00：拉取昨天数据

## 数据拉取控制

### 手动拉取单个Collector

**示例：拉取stock_daily单日数据**

```bash
cd /home/my/claude-project/AData
python3 << 'EOFPYTHON'
import sys
from pathlib import Path
sys.path.insert(0, str(Path.cwd() / 'code' / 'backend'))

from src.collectors.daily_collector import DailyCollector
from src.core.tushare_api import TushareAPI
from src.core.database import Database
import yaml

# 加载配置
with open('code/backend/config/config.yaml', 'r') as f:
    config = yaml.safe_load(f)

api = TushareAPI(config['tushare'])
db_path = 'database/adata.db'

collector = DailyCollector(db_path, api)
count = collector.run(trade_date='20260410')
print(f"✓ 拉取成功: {count}条记录")
EOFPYTHON
```

**创建批量拉取脚本：**


### 快照生成时机

**推荐时机：**
- 每30-90分钟自动生成（interval配置）
- 重要数据拉取完成后手动生成

- 数据备份（防止主库损坏）
- 跨项目数据共享（双位置快照）

## 游标状态查看

### 查看所有游标

**SQL查询：**
```sql
SELECT 
    table_name,
    cursor_strategy,
    cursor_value,
    status,
    last_fetch_time,
    last_record_count,
    updated_at
FROM global_cursor
ORDER BY table_name;
```

---

### 查看特定表游标

**示例：查看stock_daily游标**
```sql
SELECT * FROM global_cursor WHERE table_name = 'stock_daily';
```

**字段解释：**
- cursor_strategy: 游标策略（none/daily_trade/daily_natural/yearly）
- cursor_value: 游标值（YYYYMMDD或YYYY或'completed'）
- status: 状态（pending/running/success/failed）
- last_fetch_time: 最后拉取时间
- last_record_count: 最后拉取记录数

---

### 重置游标

**重置单个表游标：**
```sql
UPDATE global_cursor
SET cursor_value = NULL, status = 'pending'
WHERE table_name = 'stock_daily';
```

**重置所有游标：**
```sql
UPDATE global_cursor
SET cursor_value = NULL, status = 'pending';
```

**注意：** 重置游标会导致重新拉取数据，谨慎操作！

## 异常处理

### 异常1：API超时

**现象：**
```
TimeoutError: timed out
ReadTimeoutError: Read timed out (read timeout=30)
```

**原因：**
- API代理服务器响应慢
- 网络连接不稳定

**解决方案：**
1. 增加超时时间（修改TushareAPI timeout）
2. 等待API恢复
3. 使用重试机制

---

### 异常2：IP数量超限

**现象：**
```json
{
  "code": 40204,
  "msg": "您的IP数量超限，最大数量为2个！"
}
```

**原因：**
- 多台机器同时使用Token
- 多进程并发调用API

**解决方案：**
1. 检查使用Token的机器数量（≤2）
2. 停止其他机器的API调用
3. 等待IP计数清零（可能需要几分钟）
4. 联系代理提供商升级套餐

---

### 异常3：Token验证失败

**现象：**
```json
{
  "code": 40101,
  "msg": "您的token不对，请确认。"
}
```

**原因：**
- Token填写错误
- 使用官方地址而非代理地址

**解决方案：**
1. 检查config.yaml的token值
2. 确认api_url为代理地址（http://lianghua.nanyangqiankun.top）
3. 联系代理提供商确认Token有效性

---

### 异常4：游标更新失败

**现象：**
- 游标status为'failed'
- last_fetch_time长时间未更新

**诊断：**
```sql
SELECT table_name, status, last_fetch_time
FROM global_cursor
WHERE status = 'failed';
```

**解决方案：**
1. 查看日志（logs/adata.log）定位错误原因
2. 修复问题后重置游标：
```sql
UPDATE global_cursor
SET status = 'pending'
WHERE table_name = 'problem_table';
```
3. 重新执行拉取

---

### 异常5：数据库文件损坏

**现象：**
```
DuckDBError: Database file is corrupted
```

**解决方案：**
1. 从快照恢复：
```bash
cp database/adata_snapshot.db database/adata.db
```

2. 如果快照也损坏，重新初始化：
```bash
python3 scripts/setup_database.py
```

3. 重新拉取数据（从游标记录的日期开始）

### C. 紧急操作手册

**紧急情况1：数据库损坏**
```bash
# 1. 停止所有进程
# 2. 从快照恢复
cp database/adata_snapshot.db database/adata.db
# 3. 重启后端
python3 code/backend/main.py --snapshot --no-fetch
```

**紧急情况2：API持续超时**
```bash
# 1. 检查API地址
curl http://lianghua.nanyangqiankun.top
# 2. 临时切换到官方地址（可能不支持）
# 3. 联系代理提供商
```

```bash
# 1. 查看磁盘使用
df -h
# 2. 清理历史备份
rm database/adata_backup_*.db

```
